# Glossaire

Termes métier (français, utilisés dans la documentation) et leur nom dans le code (anglais).
Un terme ajouté ici doit être utilisé tel quel partout.

## Le projet et le groupe

| Terme métier          | Nom de code        | Définition                                                                                                                                                                                                                                 |
| --------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Voyage                | `Trip`             | Le projet : un groupe, ses envies, ses devis, et à la fin le voyage réalisé. Racine des données du voyage.                                                                                                                                 |
| Membre                | `Member`           | Personne qui a accès au voyage dans Voyager : consulte, modifie, crée des devis, vote.                                                                                                                                                     |
| Voyageur              | `Traveler`         | Une personne qui fait des voyages, réutilisable d'un voyage à l'autre : nom, pseudo, date de naissance, avatar, description. Un voyageur n'est pas forcément un utilisateur (un enfant, par exemple) ; il pourra être associé à un membre. |
| Utilisateur           | `User`             | La personne qui utilise Voyager sur ce poste. Toujours un voyageur : son profil, créé au premier lancement, ne peut pas être supprimé.                                                                                                     |
| Voyageurs du voyage   | `Trip.Travelers`   | Les voyageurs ajoutés à un voyage, chacun une fois, dans l'ordre d'ajout. Retirer un voyageur d'un voyage ne supprime pas le voyageur.                                                                                                     |
| Pseudo                | `Nickname`         | Le nom court d'un voyageur ; quand il existe, c'est lui que les écrans montrent.                                                                                                                                                           |
| Catégorie de voyageur | `TravelerCategory` | Classe utilisée par les tarifs : adulte, enfant…                                                                                                                                                                                           |
| Envie                 | `Wish`             | Une idée émise pendant l'idéation : un thème, une destination ou une activité qu'on aimerait faire.                                                                                                                                        |
| Thème                 | `Theme`            | Une orientation du voyage (nature, culture, plage…), utilisée pour classer les envies.                                                                                                                                                     |
| Destination           | `Destination`      | Un lieu envisagé pour le voyage, en général une zone (pays, région, ville).                                                                                                                                                                |

## Devis et programme

| Terme métier   | Nom de code                 | Définition                                                                                                                                   |
| -------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Devis          | `Quote`                     | Une simulation du voyage : un programme jour par jour et les prestations choisies, avec leur prix. Chaque membre peut créer les siens.       |
| Vote           | `Vote`                      | Le classement d'un membre : il donne des points dégressifs aux devis, le plus à son préféré.                                                 |
| Score          | `Score`                     | La somme des points reçus par un devis ; sert à classer les devis, pas à décider.                                                            |
| Devis retenu   | `Quote` (statut `Accepted`) | Le devis qu'un membre retient d'un clic, après le vote et la discussion. Révisable : on peut en retenir un autre plus tard.                  |
| Facture        | `Invoice`                   | Le voyage final : le devis retenu, complété par les montants réellement payés et par qui. Terme interne, par analogie avec un projet client. |
| Jour           | `Day`                       | Une journée du voyage ; unité de base du programme.                                                                                          |
| Créneau        | `TimeSlot`                  | Une plage horaire dans un jour (ex. le 12, de 10 h à 12 h), imposée par certaines réservations.                                              |
| Étape          | `Stop`                      | Un séjour en un lieu sur une période (ex. « 3 nuits à Lisbonne »).                                                                           |
| Trajet         | `Leg`                       | Le déplacement entre deux lieux : moyen de transport, durée, distance.                                                                       |
| Ligne de devis | `QuoteLine`                 | Une prestation placée dans un devis : quel jour et quel créneau, en quelle quantité, pour quels voyageurs, à quel prix.                      |
| Faisabilité    | `Feasibility`               | Le verdict sur une journée : le programme tient-il, vu les distances, les transports, les horaires et les créneaux ?                         |

## Réservations et engagements

| Terme métier            | Nom de code          | Définition                                                                                                                     |
| ----------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Réservation             | `Booking`            | Une prestation réservée ailleurs (transport, hébergement, activité) et enregistrée ici, avec sa référence.                     |
| Engagement              | `Commitment`         | Une réservation ou un paiement déjà fait. Il contraint les devis : on ne peut plus l'ignorer.                                  |
| Conditions d'annulation | `CancellationPolicy` | Ce que coûte l'abandon d'un engagement : remboursable, frais, non remboursable.                                                |
| Compatibilité           | `Compatibility`      | Le verdict sur un devis : respecte-t-il les engagements ? Sinon, il est incompatible ou doit intégrer le coût de leur abandon. |

## Catalogue et tarifs

| Terme métier       | Nom de code     | Définition                                                                                                                                                            |
| ------------------ | --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Catalogue          | `Catalog`       | L'ensemble des prestations connues, dans lequel on pioche pour construire les devis.                                                                                  |
| Prestation         | `Offer`         | Un produit ou service qu'on peut payer : vol, nuit d'hôtel, activité, ligne de bus, visa… Rattachée à zéro, un ou plusieurs lieux. Son type est fourni par un plugin. |
| Type de prestation | `OfferType`     | Une catégorie générique de prestation (hôtel, bus, visa…), commune à tous et fournie par un plugin.                                                                   |
| Tarif              | `Rate`          | Un prix d'une prestation, avec sa base de calcul, sa devise et éventuellement la catégorie de voyageur visée. Indicatif dans les données de référence.                |
| Base de calcul     | `PricingBasis`  | Comment un tarif s'applique : par personne, par unité, au forfait, à l'heure, à la nuit, au jour.                                                                     |
| Type de coût       | `CostType`      | Direct (`Direct`), induit (`Induced`) ou indirect (`Indirect`).                                                                                                       |
| Coût direct        | `Direct`        | Ce qu'on achète pour le voyage : vol, hôtel, activité.                                                                                                                |
| Coût induit        | `Induced`       | Ce que le voyage oblige à payer : visa, assurance, vaccins.                                                                                                           |
| Coût indirect      | `Indirect`      | Ce qu'il faut pour vivre chaque jour sur place : repas, petites dépenses.                                                                                             |
| Lieu               | `Place`         | Un point ou une zone géographique nommé (pays, ville, hôtel, arrêt de bus…), avec coordonnées WGS 84. Les lieux forment une hiérarchie : un lieu a un lieu parent.    |
| Moyen de transport | `TransportMode` | À pied, voiture, bus, train, avion, bateau…                                                                                                                           |
| Ligne de transport | `TransitLine`   | Une ligne précise rattachée à un lieu (« bus ligne A » à Barcelone) avec, si on les connaît, ses arrêts, horaires et prix.                                            |

## Budget et répartition

| Terme métier         | Nom de code     | Définition                                                                                              |
| -------------------- | --------------- | ------------------------------------------------------------------------------------------------------- |
| Budget               | `Budget`        | Les montants d'un devis ou de la facture, ventilés par type de coût, par jour et par voyageur.          |
| Montant prévu        | `PlannedAmount` | Le prix attendu d'une ligne, issu du tarif.                                                             |
| Montant payé         | `PaidAmount`    | Ce qui a réellement été payé.                                                                           |
| Prix du voyage       | `TripPrice`     | Le total de ce qui se réserve ou se paie à l'avance.                                                    |
| Argent sur place     | `SpendingMoney` | Ce qu'il faut avoir pour vivre le voyage, jour par jour.                                                |
| Règle de répartition | `SplitRule`     | Comment un coût se partage entre voyageurs (à parts égales, au prorata, au réel, part réduite enfant…). |
| Part                 | `Share`         | Ce qu'un voyageur doit sur un coût, selon la règle de répartition.                                      |
| Paiement             | `Payment`       | Un montant payé par un membre, pour une ou plusieurs lignes.                                            |
| Remboursement        | `Settlement`    | Un virement entre membres pour équilibrer les comptes à la fin.                                         |
| Devise               | `Currency`      | Code ISO 4217 accompagnant tout montant.                                                                |

## Données et plateforme

| Terme métier                   | Nom de code                                           | Définition                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------ | ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Données de référence           | `ReferenceData`                                       | Les données partagées entre les voyages d'un même groupe (pas une base communautaire), rattachées à des lieux : prestations, lignes de transport, tarifs indicatifs. Jamais d'information personnelle.                                                                                                                                                                                               |
| Données du voyage              | `TripData`                                            | Ce qui appartient à un voyage : membres, envies, devis, prix concrets, paiements. Visible des seuls membres.                                                                                                                                                                                                                                                                                         |
| Source de données              | `DataSource`                                          | D'où vient une donnée : saisie manuelle, API, extraction ciblée, paquet de données, import. Chaque donnée garde sa source et sa date.                                                                                                                                                                                                                                                                |
| Format d'échange               | `ExchangeFormat`                                      | Le format de fichier standardisé, documenté et versionné des données de référence. Extensible par les plugins.                                                                                                                                                                                                                                                                                       |
| Paquet de données              | `DataPackage`                                         | Un fichier au format d'échange qui regroupe des données de référence (ex. « Barcelone : transports et musées »), à importer ou partager. Jamais de données de voyage.                                                                                                                                                                                                                                |
| Extraction ciblée              | `PageExtraction`                                      | Récupérer les informations utiles d'une page précise dont on donne l'adresse (la fiche d'un hôtel). Pas d'aspiration de sites entiers.                                                                                                                                                                                                                                                               |
| Connecteur                     | `Connector`                                           | Un plugin qui va chercher des données dans une source (une API de vols, la page d'un site d'hôtels…).                                                                                                                                                                                                                                                                                                |
| Contrat                        | `Contract`                                            | L'interface qu'un élément doit respecter pour être branché sur le cœur de Voyager.                                                                                                                                                                                                                                                                                                                   |
| Plugin                         | `Plugin`                                              | Un paquet (aussi appelé *add-in*), livré avec l'application ou installé par l'utilisateur, qui fournit une ou plusieurs implémentations de contrats : une partie .NET (logique) et, si besoin, un module d'interface React.                                                                                                                                                                          |
| Manifeste de plugin            | `PluginManifest`                                      | Le fichier `plugin.json` d'un plugin : identifiant, version, contrats fournis et contrats requis avec leur version (dont le contrat de base `plugin`, qui remplace la version du SDK, ADR-0017).                                                                                                                                                                                                     |
| Point d'extension              | `ExtensionPoint`                                      | Un endroit où le cœur accepte des plugins : type de prestation, base de calcul, règle de répartition, connecteur, vue, export.                                                                                                                                                                                                                                                                       |
| Registre d'extensions          | `ExtensionRegistry`                                   | Là où les plugins déclarent ce qu'ils fournissent, côté service local (`ExtensionRegistry`) et côté interface (`PluginRegistry`) ; l'application n'affiche que ce que le registre contient.                                                                                                                                                                                                          |
| État d'un plugin               | `PluginStatus`, `PluginRequest`, `PluginRequestError` | Chargé, écarté avec la raison, désactivé ou suspendu après un plantage (`PluginStatus`) ; avec, à côté, la demande en attente de redémarrage et la dernière demande en échec. Visible dans l'écran « Plugins » et, pour les chargés et écartés, dans la page « À propos ». Ne pas confondre avec le fichier d'état `state.json`, qui garde les *fiches* des plugins.                                 |
| Catalogue de plugins           | `PluginCatalog`                                       | Les plugins trouvés au démarrage dans les dossiers des plugins (livrés, installés), chargés ou écartés, et ce qu'ils fournissent.                                                                                                                                                                                                                                                                    |
| Plugin livré                   | `PluginOrigin.Shipped`                                | Un plugin qui est dans le paquet de l'application : il ne se désinstalle pas, il se désactive, et il se met à jour avec l'application.                                                                                                                                                                                                                                                               |
| Plugin installé                | `PluginOrigin.Installed`                              | Un plugin que l'utilisateur a installé depuis un paquet, rangé dans ses données : il survit aux mises à jour de l'application et se désinstalle.                                                                                                                                                                                                                                                     |
| Paquet de plugin               | `PluginPackages.EXTENSION`                            | Le fichier `.voyagerplugin` qui transporte un plugin : une archive zip, avec une signature facultative, vérifiée avant d'être posée.                                                                                                                                                                                                                                                                 |
| Boîte de dépôt                 | `inbox` (`InboxPackage`)                              | Le dossier où l'utilisateur dépose des paquets de plugin, à la main ou par « Ajouter un paquet… ».                                                                                                                                                                                                                                                                                                   |
| Demande de plugin              | `PluginRequest`, `PluginRequestEntry` (TS)            | Ce que l'utilisateur a demandé (installer, remplacer, désinstaller, activer, désactiver) et qui s'applique au prochain démarrage du service local.                                                                                                                                                                                                                                                   |
| Vérification d'un plugin       | `PluginVerification`                                  | Ce que l'application sait de l'auteur d'un plugin : « Garanti par l'application » pour un plugin livré, « Non vérifié » pour un paquet importé depuis un fichier, « Vérifié » pour un paquet signé par le projet (pas avant qu'une clé de production existe).                                                                                                                                        |
| Origine d'un plugin            | `PluginOrigin`                                        | D'où vient un plugin : « Livré avec Voyager » (dans l'application) ou « Installé par vous » (depuis un fichier).                                                                                                                                                                                                                                                                                     |
| Racine de plugins              | `PluginRoot`                                          | Un dossier qui contient des plugins, un sous-dossier chacun, avec leur origine : les plugins livrés (dossier de l'application), puis les installés (`plugins/installed` des données de l'utilisateur), lus dans cet ordre.                                                                                                                                                                           |
| Fiche d'un plugin              | `PluginRecord`                                        | Ce que le service retient d'un plugin entre deux démarrages, dans le fichier d'état `state.json` : activé ou non, date et paquet d'origine d'un installé, dernière demande en échec.                                                                                                                                                                                                                 |
| Demande en échec               | `PluginRequestError`, `PluginRequestFailure`          | Une demande de plugin qui n'a pas pu être appliquée au démarrage (plugin introuvable, geste interdit comme désinstaller un plugin livré, fichiers qui ne se laissent pas modifier) : elle reste sur le plugin, avec sa raison, sans bloquer le démarrage.                                                                                                                                            |
| Empreinte d'un paquet          | `PackageSha256`                                       | Le SHA-256 d'un paquet de plugin, montré avant l'installation et revérifié à l'application : elle prouve que le paquet n'a pas changé, pas qui l'a écrit.                                                                                                                                                                                                                                            |
| Copie de préparation           | `PluginPackageReference.StagedName`                   | La copie privée d'un paquet que Voyager fait quand on choisit de l'installer : c'est elle qui est examinée puis appliquée, le fichier de la boîte de dépôt pouvant changer ou disparaître.                                                                                                                                                                                                           |
| Examen d'un paquet             | `PackageExamination`                                  | Ce que le service trouve dans une copie de préparation, avant que l'utilisateur confirme : le plugin, ses contrats, ce qu'il apporte, et ce que l'installer ferait (nouveau, plus récent, plus ancien, réinstallation). Rien n'est installé ni exécuté.                                                                                                                                              |
| Refus d'un paquet              | `PackageRefusal`                                      | Pourquoi l'examen refuse un paquet : archive illisible, manifeste invalide, fichier déclaré absent, contrat non pris en charge, fichier ou nom interdit, place insuffisante sur le disque.                                                                                                                                                                                                           |
| Type d'installation            | `PackageInstallKind`                                  | Ce que ferait l'installation d'un paquet, comparé au plugin déjà installé sous le même identifiant : nouveau, mise à jour, retour à une version plus ancienne, réinstallation. La confirmation l'annonce.                                                                                                                                                                                            |
| Confirmation de plugin         | `ConfirmationBox`, `askConfirmation`                  | La boîte de dialogue du système qui demande l'accord de l'utilisateur avant d'installer, de remplacer, de désinstaller ou d'activer un plugin : « Annuler » par défaut, et la case « Je comprends » pour un plugin « Non vérifié ». Le module d'un plugin ne peut pas la confirmer à sa place.                                                                                                       |
| Redémarrer pour appliquer      | `PluginManagementBridge.restart`                      | Relancer le service local pour qu'il applique les demandes de plugin en attente, puis recharger la page ; l'application ne se ferme pas.                                                                                                                                                                                                                                                             |
| Écran « Plugins »              | `PluginsPage`                                         | L'écran qui montre tous les plugins connus de Voyager (origine, vérification, état, détail), la boîte de dépôt et les demandes en attente, et d'où l'on installe, remplace, désinstalle, active et désactive un plugin. Il ne dépend d'aucun plugin.                                                                                                                                                 |
| Démarrage de rétablissement    | `addRecoveryRequest`, `DisabledForRecovery`           | Le démarrage « sans les plugins installés » proposé par l'écran d'échec : les plugins installés sont désactivés pour le rétablissement, puis réactivés un à un pour retrouver celui qui fait planter.                                                                                                                                                                                                |
| Plugin suspendu                | `PluginStatus.Suspended`                              | Un plugin soupçonné d'avoir fait planter Voyager : il était en cours de chargement, ou le seul en cours d'appel. Il n'est plus chargé tant que l'utilisateur ne l'a pas désactivé pour de bon ou réactivé, avec une confirmation renforcée.                                                                                                                                                          |
| Trace d'activité               | `PluginActivity`                                      | Le fichier `activity.json` où le service note le plugin en cours de chargement et ceux en cours d'appel. Un arrêt normal l'efface ; trouvé au démarrage, il désigne le plugin d'un plantage.                                                                                                                                                                                                         |
| Version de contrat             | `ContractVersion`                                     | Un contrat publié a des versions entières (`1`, `2`…) ; dans une version on n'ajoute que de façon compatible, tout le reste crée une nouvelle version. Elle est indépendante du numéro de version du SDK et de celui d'un paquet gRPC.                                                                                                                                                               |
| Contrat fourni, contrat requis | `ContractRole.Provided`, `ContractRole.Required`      | Ce qu'un plugin déclare dans son manifeste : les contrats (avec leur version) qu'il implémente, et ceux qu'il consomme. Une dépendance entre plugins est une exigence de contrat, jamais d'un plugin précis.                                                                                                                                                                                         |
| Contrat de base                | `ContractVersions.PLUGIN`                             | Le contrat `plugin` (`IPlugin`, `IPluginBuilder`) que l'application fournit à tous les plugins : chaque plugin le requiert, aucun ne le fournit. Il remplace l'ancien champ `sdk` du manifeste (ADR-0017).                                                                                                                                                                                           |
| Version prise en charge        | `ContractSupport`, `ContractUseState`                 | Une version de contrat que l'application accepte (prise en charge ou dépréciée). Une version obsolète, ou inconnue de l'application (plugin trop récent, ou contrat requis que l'application ne fournit pas encore), n'est **pas prise en charge** : le plugin est écarté avec « contrat non pris en charge ».                                                                                       |
| Adaptateur de contrat          | `ContractAdapter`                                     | Ce qui garde une ancienne version d'un contrat en état de marche quand une nouvelle paraît : un adaptateur descendant (un consommateur `V1` face à un service `V2`) ou montant (un fournisseur `V1` face à un hôte qui attend `V2`). Chaque version prise en charge s'adapte directement à la version courante.                                                                                      |
| Contrat obsolète               | `ContractVersionState.Obsolete`                       | Une version de contrat qui n'est plus prise en charge : l'adaptateur a disparu, ou n'a jamais pu exister. Les plugins qui l'utilisent (qui la fournissent ou la requièrent) sont écartés (« contrat non pris en charge »). Elle est dépréciée d'abord quand c'est possible, obsolète dès la parution de la nouvelle quand l'adaptation est impossible.                                               |
| Contrat déprécié               | `ContractVersionState.Deprecated`                     | Une version de contrat qui fonctionne encore, par un adaptateur, mais qui sera retirée : la vue avertit que les plugins qui l'utilisent devront être remplacés.                                                                                                                                                                                                                                      |
| Plugin suspendu                | `SuspendedPlugin`                                     | Un plugin que Voyager ne charge pas parce qu'il est soupçonné d'avoir fait planter le service ; l'utilisateur décide de le désactiver ou de le réactiver.                                                                                                                                                                                                                                            |
| Composant versionné            | `VersionedComponent`                                  | L'application, le SDK ou un plugin : chacun a son numéro de version, calculé de son propre historique (étiquettes `v*`, `sdk/v*`, `plugins/<id>/v*`) et jamais écrit à la main (ADR-0007).                                                                                                                                                                                                           |
| Raison d'écartement            | `PluginRejectionReason`                               | Pourquoi un plugin n'est pas utilisé : manifeste invalide, identifiant en double (déjà livré, ou déjà installé), contrat non pris en charge (qui remplace « SDK incompatible », ADR-0017), échec du chargement, inscription non déclarée et, avec les dépendances, prérequis non fourni, dépendance circulaire, autre fournisseur actif.                                                             |
| Source de faits de diagnostic  | `DiagnosticFactSource`                                | Le point d'extension de la preuve des plugins : ce qui fournit des faits de diagnostic. Le service local en est une, un plugin peut en être une autre.                                                                                                                                                                                                                                               |
| Fait de diagnostic             | `DiagnosticFact`                                      | Une information sur le service fournie par une source : un libellé traduisible et une valeur (texte, nombre ou instant), affichée dans la page « À propos ».                                                                                                                                                                                                                                         |
| Panneau de plugin              | `DiagnosticFactPanel`                                 | Le composant React par lequel un plugin présente lui-même les faits de sa source, à la place de la liste standard de la page « À propos ».                                                                                                                                                                                                                                                           |
| Modules partagés               | `SharedModules`                                       | React, Fluent UI, `@fluent/react` et le SDK d'interface, que la page partage avec les plugins par son *import map* : une seule copie de React.                                                                                                                                                                                                                                                       |
| Service local                  | `LocalService`                                        | Le processus .NET embarqué dans l'application de bureau : logique métier, base locale, hors-ligne, synchronisation.                                                                                                                                                                                                                                                                                  |
| Serveur du groupe              | `GroupServer`                                         | Le serveur hébergé qui accueille plusieurs groupes : il centralise les données de chacun, séparément, et diffuse les changements à leurs membres.                                                                                                                                                                                                                                                    |
| Groupe                         | `Group`                                               | Les personnes qui organisent leurs voyages ensemble dans Voyager ; un membre peut appartenir à plusieurs groupes, et ne voit que les données des siens.                                                                                                                                                                                                                                              |
| Invitation                     | `Invitation`                                          | Le lien qui permet à une personne de rejoindre un groupe comme membre.                                                                                                                                                                                                                                                                                                                               |
| Mode solo                      | `SoloMode`                                            | L'utilisation de Voyager sans serveur, avec le seul service local.                                                                                                                                                                                                                                                                                                                                   |
| Vue                            | `View`                                                | Une façon de présenter un voyage : timeline, planning, carte, programme, graphiques. Fournie par un plugin.                                                                                                                                                                                                                                                                                          |

## Carnet de voyage (plus tard)

| Terme métier        | Nom de code    | Définition                                                                            |
| ------------------- | -------------- | ------------------------------------------------------------------------------------- |
| Carnet              | `Journal`      | Le récit d'un voyage : l'ensemble de ses entrées.                                     |
| Entrée de carnet    | `JournalEntry` | Un texte daté, rattaché à un jour, une étape ou un lieu, pouvant contenir des photos. |
| Photo               | `Photo`        | Une image rattachée à une entrée, avec date, position et tags.                        |
| Idée pour plus tard | `Idea`         | Une envie notée pendant un voyage, à reprendre dans un prochain.                      |
